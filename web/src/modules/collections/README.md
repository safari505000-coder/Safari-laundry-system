# `modules/collections/` — V20.6 Collections Workspace

> Generated by V20.6 — Phase 6A.

Domain module for the V20.5 **Collections Workflow** (CollectionsAccount, PromiseToPay, escalation, SLA monitoring). Pages here power the Phase 7 *Collections Operations Workspace*.

## Structure

```
web/src/modules/collections/
├── api/            # typed API clients
├── components/     # workspace-specific composites
├── hooks/          # domain hooks (promises, escalation, SLA)
├── pages/          # full pages
├── state/          # collections-scoped cache / selectors
├── types/          # shared DTO types
├── utils/          # pure helpers
└── index.ts        # barrel
```

## Conventions

1. **Read canonical numbers from `modules/finance`.** This module owns the *workflow* (stage, promise lifecycle, SLA, notes), not the *amounts*.
2. **Status transitions go through dedicated mutation hooks** so `invalidateFinancial('finance:collections:…')` can be chained reliably.
3. **No deep imports across siblings.** Always go through `index.ts`.

## Sibling V20.6 domain modules

- `modules/finance/` — canonical numbers, ledger, reconciliation, observability
- `modules/customer360/` — unified financial timeline
- `modules/risk/` — risk badges + recalculation surface
- `modules/fraud/` — fraud alerts surface
