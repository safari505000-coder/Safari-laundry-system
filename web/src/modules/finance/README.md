# `modules/finance/` — V20.6 Financial Workspace

> Generated by V20.6 — Phase 6A.

This is the **domain-oriented** finance module that complements the existing **role-oriented** structure (`accountant/`, `call-center/`, `owner/`, …). Use it when:

- you're implementing a **financial workflow** rather than a **role-specific page**,
- you need a **canonical Financial UI Kit component** (DebtCard, AgingBadge, RiskBadge, …) rather than a one-off,
- you need a **typed financial API hook** with cache + invalidation semantics.

## Structure

```
web/src/modules/finance/
├── api/            # typed API clients (TanStack-Query-shaped hooks)
├── components/     # Financial UI Kit — DebtCard, AgingBadge, …
├── hooks/          # higher-level domain hooks (composition)
├── pages/          # full pages owned by this module
├── state/          # client-side normalized cache helpers
├── types/          # shared DTO types
├── utils/          # pure helpers (formatters, comparators)
└── index.ts        # barrel exports
```

## Conventions

1. **Never reach into another module's internals.** Cross-module access goes through that module's `index.ts` barrel only.
2. **Never import from `pages/` outside this module.** Pages are leaves of the dependency graph.
3. **Avoid duplicating debt math.** The server is canonical (V20.4 / V20.5 / V20.6). Frontend formats the server's numbers.
4. **Use the Financial UI Kit primitives** for any debt / aging / risk display so visual tone stays consistent.

## Sibling V20.6 domain modules

The same conventions apply to:

- `modules/collections/` — Collections workflow, promise-to-pay, escalations
- `modules/customer360/` — Unified customer financial timeline
- `modules/risk/` — Risk badges, fraud alerts surface
- `modules/accounting/` — Accountant reports + period close
- `modules/dashboards/` — Cross-domain dashboards (owner overview, etc.)
