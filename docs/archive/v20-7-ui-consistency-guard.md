# V20.7 — UI_CONSISTENCY_GUARD

> Generated by V20.7 — Phase 7.

Codifies the V20.7 contract: **every monetary value the UI shows
MUST come from a server-canonical source** (FinancialSnapshot,
canonical debt API, journal-backed DTO). No client-side math.

## 1. Two layers of enforcement

V20.7 stacks a **static** guard on top of the V20.5/V20.3 **runtime**
guard so drift is caught both at PR time and in production:

| Layer | What it checks | Where |
| --- | --- | --- |
| Static (V20.7 — Phase 7) | New code never adds client-side KD math | `web/src/modules/finance/components/v20-7-ui-consistency.test.ts` |
| Runtime (V20.5 — Phase 1) | Stored debt sources stay within tolerance | `src/finance/audit/ui-drift-inspector.service.ts` |

## 2. Forbidden patterns (static)

The static spec scans every file under:

- `web/src/modules/finance/components/`
- `web/src/modules/collections/components/`
- `web/src/modules/collections/pages/`

…and fails the build if any of these patterns appear:

| Pattern | Why it's banned |
| --- | --- |
| `parseFloat(...someKd)` | Loses Decimal precision; the server already returned a string. |
| `someKd.toFixed(...)` | Re-formats a server-canonical KD string and may drop trailing precision. |
| `someKd + something` (also `-`, `*`, `/`) | Client-side arithmetic on currency. |
| `Math.round(...someKd...)` | Rounding policy belongs to the ledger, not the UI. |
| `Number(someKd)` | Same precision risk as `parseFloat`. |
| `.reduce(... someKd ...)` | Computing a client-side total. |

Tests, comments, and JSDoc are stripped before scanning so prose
that *describes* these patterns does not trip the guard.

## 3. Where canonical numbers come from

Every Phase 3 component reads from one of these contracts:

| Component | Canonical source field(s) | API route |
| --- | --- | --- |
| `DebtCard` | `customer360.financials.canonicalDebtKd`, `canonicalNetDebtKd`, `walletBalance` | `/api/customer-360/:id` |
| `CustomerFinancialHeader` | `remainingDebtKd`, `walletBalanceKd` (server-canonical strings) | `/api/customer-360/:id` |
| `OutstandingTable` | `totalKd`, `paidKd`, `remainingKd` (per row, server-canonical) | `/api/finance/outstanding/*` |
| `FinancialTimeline` | `amountKd` (per row, server-canonical) | `/api/finance/observability/customer/:id/timeline` |
| `JournalEntryCard` / `JournalEntryView` | `amountKd` from `JournalSourceService` | `/api/finance/journal/*` |
| `KPIWidget` / `FinancialStatCard` | Pre-formatted strings from `observability/overview` | `/api/finance/observability/overview` |
| `ReconciliationStatus` | `journalArKd`, `snapshotArKd` from `ReconciliationStatusDTO` | `/api/finance/observability/reconciliation` |
| `MoneyFlowCard` | `inKd`, `outKd` from `JournalSourceService` aggregations | `/api/finance/journal/cash-flow` |
| `FinancialHealthIndicator` | `healthScore` from observability overview | `/api/finance/observability/overview` |

The scanner verifies the **shape** of the contract — that the
fields end in `Kd` and are read straight into a `<span>`,
`<time>`, or formatter that does not mutate them.

## 4. Permitted display-side helpers

The following are **explicitly allowed**:

- `Number.parseFloat(s).toLocaleString('en', { ... })` inside the
  `CustomerFinancialHeader` component for thousand-separator
  formatting. This is layout-only and never changes the underlying
  precision; it triggers only on display, never on storage.
- `Math.floor` / `Math.ceil` for **layout indices** (e.g. computing
  the visible slice of a virtualized list). The static guard
  whitelists these because they touch viewport math, not money.
- The locale-aware `toLocaleDateString` for date headers.

## 5. Runtime safety net

The V20.5 `UiDriftInspectorService` runs against production data
and classifies any divergence between the canonical debt source
and a UI-visible field as `UI_DRIFT`, `LEGACY_READER`, or
`CRITICAL`. V20.7 inherits this without change.

The combination is bank-grade:

```
   Static guard (V20.7)         Runtime guard (V20.5)
   ───────────────────────      ───────────────────────
   Catches a developer who      Catches an operator who
   adds new UI math.            sees a stale row.
```

## 7. Rollback

The guard is a single test file. Removing
`v20-7-ui-consistency.test.ts` removes the enforcement; the
runtime drift inspector continues to operate. No production
behaviour changes when the guard is disabled — it is purely a
build-time safety net.
