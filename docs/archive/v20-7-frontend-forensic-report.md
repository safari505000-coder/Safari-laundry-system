## 1. Architecture problems

### 1.1 Three coexisting top-level shapes

The frontend currently keeps **three** organisational shapes side-by-side:

1. `web/src/pages/` — original flat page collection (76 files).
2. `web/src/components/` — original flat component bucket (14 files).
3. `web/src/modules/` — modern V19/V20-era domain modules (133 files; introduced opportunistically per role/feature).

Result: no canonical "where does this live?" answer. New developers default to `pages/` for simplicity, which keeps growing.

### 1.2 `App.tsx` is a single mega-router

- 1,089 lines, 94 page imports, **0 lazy loads**.
- Every page ships in the initial JS bundle even though most users hit one or two routes per session.
- Adding a route requires editing the central file → merge-conflict magnet.

### 1.3 `web/src/lib/api.ts` is a 6.2K-LOC god-file

- One file owns every HTTP type and every fetcher.
- No domain split (no `api/finance.ts`, `api/payroll.ts`, …).
- A trivial type tweak triggers a tsc rebuild that touches the whole app.
- Easy to introduce duplicated DTOs because nobody can find what already exists.

### 1.4 Direct API usage inside pages

35+ pages call `apiJson` / `apiFetch` directly:

```
subscribers-page.tsx           10 direct calls
monthly-report-full-print-page  7
payroll-unified-page            5 + 6 in payroll-page
reports-page                    5
expenses-page                   4
…
```

Result: no caching, no deduplication, no consistent loading/error UX, no retry policy, no cancel-on-unmount in many places.

### 1.5 Business logic baked into pages

`subscribers-page.tsx` is the worst offender:

- 89 KB / single file
- 30 `useState`/`useEffect` calls
- 36 references to canonical debt fields (mixing operational + canonical)
- 20 `parseFloat` / `toFixed` / `Math.round` calls (client-side numeric gymnastics)

`payroll-unified-page.tsx`, `staff-debts-page.tsx`, `unpaid-invoices-page.tsx`, `monthly-summary-page.tsx`, `financials-page.tsx`, `debt-holds-page.tsx`, `monthly-report-full-print-page.tsx` all sit in the **40-90 KB single-file** band and bundle business logic + UI + fetching.

### 1.6 Shared-folder abuse

`web/src/modules/shared/` increasingly absorbs anything that "could be reused" — including financial UI atoms that would be better placed in `modules/finance/components/`.

Examples:

- `modules/shared/components/finance/payment-status-chip.tsx` (a financial primitive in `shared/`)
- `modules/shared/hooks/finance/use-customer-debt.ts` (a finance domain hook in `shared/`)
- `modules/shared/hooks/finance/use-financial-snapshot.ts`
- `modules/shared/hooks/finance/use-collections-summary.ts`
- `modules/shared/hooks/finance/use-invoice-status.ts`

These belong to `modules/finance/` (Phase 6 of V20.6 introduced the right home).

### 1.7 No route-level code splitting

- `App.tsx` imports all 94 pages eagerly.
- No `Suspense` boundary anywhere in the routing tree.
- Initial bundle pays for every page even on a login screen.

### 1.8 Mixed UI/business logic

Patterns observed:

- Pages that fetch, normalise, aggregate, format, and render — all in one component.
- Pages that import `apiJson` directly AND contain `useEffect` reduce/sum/groupBy logic.
- DTO contracts re-derived in-place rather than typed once in a domain `api/` module.

### 1.9 Inconsistent tables

There is no canonical `DataTable`, `OutstandingTable`, or virtualised list in legacy pages. Each table is hand-rolled with `<table><thead><tbody>` plus its own pagination + sort logic. Result:

- Inconsistent sort behaviour
- Inconsistent empty / loading / error UX
- Inconsistent zebra striping, padding, and a11y
- Zero virtualization → 10K-row outstanding renders 10K DOM rows

### 1.10 Duplicated modals

Customer-action modals (block/unblock, payments, dispatch, refund, invoice cancel, etc.) appear in multiple variants across `pages/` and `modules/`. A central `modules/<domain>/modals/` folder is missing for most domains.

## 2. Performance bottlenecks

| Bottleneck | Impact | Mitigation |
| --- | --- | --- |
| 0 lazy routes | Initial bundle ships every page | Route-level `lazy()` + `Suspense` in `App.tsx` |
| Tables without virtualization | 10K rows = 10K DOM nodes | Use `WindowedList` from `modules/finance/components` |
| Direct `apiJson` calls without cache | Every page mount = full refetch | `useFinancialQuery` + global cache |
| Mega `api.ts` (6.2K LOC) | tsc + Vite have to re-process the entire file on tiny changes | Split into per-domain `api/*.ts` files |
| `subscribers-page.tsx` (89 KB) | Renders thousands of subscribers in one pass | Split + virtualize + memoize selectors |
| No `Suspense` boundaries | Loading states inconsistent and blocking | Wrap pages in suspense with skeletons |
| Eager Excel/PDF imports inside pages | Heavy libs (`exceljs`, `pdf-lib`) bundled into the main chunk | Dynamic `import()` on the actual click |

## 3. UX pain points

- **No keyboard-first workflow** outside the new V20.6 Phase 7 Collections Workspace.
- **Inconsistent loading UX**: some pages show a `Loader2` spinner, others show "loading…" text, others freeze the table.
- **No skeleton loaders** anywhere outside the tiny `modules/shared/components/skeletons` set (limited).
- **No financial empty states**: a customer with zero debt looks identical to a failed fetch.
- **Inconsistent error states**: some pages show a toast, others show an inline message, others silently log and render nothing.
- **No bulk actions** on most tables.
- **No global keyboard shortcuts** (only Phase 7 Collections Workspace has Alt+P/M/E/N).
- **Dark-mode coverage is patchy**: many pages lack `dark:` variants.

## 4. Scalability risks

| Risk | Severity | Why |
| --- | --- | --- |
| `App.tsx` will hit ~ 2K LOC by V21 | MEDIUM | New routes keep being added centrally |
| `lib/api.ts` will hit ~ 10K LOC | HIGH | Every domain stuffs DTOs into one file |
| `pages/` will hit ~ 100 files | MEDIUM | New work goes there by default |
| Tables can't scale past ~ 5K rows | HIGH | No virtualization |
| State duplication between pages | HIGH | No shared cache for legacy pages |

## 7. Recommended structure (target for Phase 2)

```
web/src/
├── modules/
│   ├── finance/         (canonical numbers, UI Kit, observability, cache)
│   ├── collections/     (workflow + Operations Workspace)
│   ├── customer360/     (cross-domain timeline)
│   ├── subscribers/     (subscriptions surface — split from pages/)
│   ├── dashboards/      (owner / GM / accountant overviews)
│   ├── accounting/      (chart of accounts, period close, journal viewer)
│   ├── risk/            (risk recalculation & history)
│   ├── fraud/           (fraud alerts queue)
│   ├── callcenter/      (CC dashboard + Operations Workspace)
│   └── shared/          (truly cross-cutting: nav, auth, layout shells)
│
├── lib/
│   ├── api/             (per-domain typed clients — split from api.ts)
│   │   ├── auth.ts
│   │   ├── finance.ts
│   │   ├── collections.ts
│   │   └── …
│   ├── format/          (formatters, date / KD)
│   └── design/          (design tokens, color system)
│
├── app/
│   ├── routes.ts        (declarative route table — replaces App.tsx body)
│   └── App.tsx          (thin shell + Suspense + ErrorBoundary)
│
└── pages/               (LEGACY — frozen, opportunistic migration only)
```

Migration policy: **frozen**. No new pages in `pages/`; existing pages migrate to a module on their next material change.
