## 3. Why one chip stays (the grandfathered case)

The single legacy `PaymentStatusChip` consumer is
`pages/unpaid-invoices-page.tsx`. A clean migration would change
**user-visible Arabic text**:

| Status | Legacy label | V20.7 label |
| --- | --- | --- |
| UNPAID | `غير مدفوع` (no ة) | `غير مدفوعة` (with ة) |
| PARTIAL(LY_PAID) | `مدفوع جزئيًا` | `مدفوعة جزئياً` |
| PAID | `مدفوع` | `مدفوعة` |

The text difference is grammatically correct in both directions
(masculine vs feminine agreement with the implied noun). For a
financial system, **changing user-visible text mid-mission**
deserves QA review and a release note. V20.8 therefore:

1. **Marks the legacy chip `@deprecated`** in JSDoc with a clear
   migration plan.
2. **Grandfathers the one consumer** in the static guard
   allow-list.
3. **Schedules the migration** for the next maintenance touch on
   `unpaid-invoices-page.tsx` so the text change ships with QA.

This matches the V20.8 "no risky changes" charter: documented,
guarded, but not forced.

## 4. New static guard (build-fail on regression)

`web/src/modules/finance/components/v20-8-component-consolidation.test.ts`
fails the build if any **new** import lands on the deprecated
modules. The guard:

- Strips block + line comments before scanning (so JSDoc
  references like the one above don't trigger).
- Excludes `*.test.*` / `*.spec.*` files (they contain banned
  strings as literals).
- Allows self-imports (the deprecated file itself).
- Maintains an explicit `grandfathered` allow-list — adding to
  it requires reading the V20.8 LEGACY_DISCOVERY_REPORT first.

Result locked into CI:

```
 ✓ no NEW imports of modules/shared/components/finance/payment-status-chip
 ✓ no NEW imports of modules/call-center/outstanding/components/outstanding-table
 ✓ no NEW imports of components/layout/Sidebar
 ✓ no NEW imports of components/layout/Header
```

## 6. Risk analysis

| Risk | Severity | Mitigation |
| --- | ---: | --- |
| Static guard mis-classifies a JSDoc reference as an import | LOW | Comments stripped before scanning; tested |
| New developer adds an import to a deprecated module | MITIGATED | Build now fails with a clear rationale message |
| Grandfathered consumer slips out of date (file moves) | LOW | Allow-list keys are POSIX-style relative paths; a renamed file would break the guard, alerting the maintainer |
| Migration of `unpaid-invoices-page.tsx` ships text changes | MEDIUM | Documented; QA must review the migration commit |
