## 2. The canonical UI primitives

### 2.1 Single money formatter — `web/src/lib/kwd.ts`

```ts
// Sole canonical money formatter for the entire frontend.
// Adding a new monetary display surface MUST import from this file.

formatKwdAmount(s)         → "1234.500"            (3dp, no suffix, no grouping)
formatKwdLabel(s)          → "1234.500 د.ك"        (3dp, suffix, no grouping)
formatKwdLabelGrouped(s)   → "1,234.500 د.ك"       (3dp, suffix, locale grouping — KPIs)
formatSignedKwdLabel(s)    → "+1234.500 د.ك"       (3dp, signed, suffix)
sumKwdStrings(values[])    → "1234.500"            (3dp; sum-of-display only)
subtractKwdStrings(a, b)   → "-1.000"              (3dp; receipt subtractions)
```

**Forbidden alternatives:**

- ❌ Local `function formatKwd*(...)` definitions in any other file.
- ❌ Local `KWD_SUFFIX` constants.
- ❌ `value.toFixed(3)` calls outside `web/src/lib/kwd.ts`.
- ❌ `parseFloat(...)` chained with arithmetic on `Kd` strings.

The 96 V21 guards in
`src/finance/v21-canonical-banking-guards.spec.ts` enforce these
rules on every CI build. New surfaces opt in by adding their path
to `singleFormatterGuardedFiles`.

## 3. Enterprise design rules

### 3.1 Money display

**Rule:** Every monetary value MUST flow through `web/src/lib/kwd.ts`.

```tsx
// ✅ CORRECT
import { formatKwdLabel } from '@/lib/kwd';
<span>{formatKwdLabel(row.amountKd)}</span>

// ❌ FORBIDDEN — local formatter
const formatKd = (n: number) => `${n.toFixed(3)} د.ك`;

// ❌ FORBIDDEN — toFixed
<span>{Number(row.amountKd).toFixed(3)} د.ك</span>

// ❌ FORBIDDEN — parseFloat arithmetic
<span>{(parseFloat(a) + parseFloat(b)).toFixed(3)}</span>
```

**Enforcement:** 96 V21 guard cases in
`src/finance/v21-canonical-banking-guards.spec.ts`. Build-fail on
violation.

### 3.2 Date display

**Rule:** Use `Intl.DateTimeFormat` or `toLocaleDateString` with
explicit locale. Never roll your own date parser.

```tsx
// ✅ CORRECT
new Date(row.createdAt).toLocaleDateString('ar-KW', { dateStyle: 'medium' });

// ❌ DISCOURAGED — manual date arithmetic
const day = new Date(s).getDate();
const month = new Date(s).getMonth() + 1;
return `${day}/${month}`;
```

### 3.3 Spacing / sizing

**Rule:** Use the Tailwind 4-point grid (`p-1 / p-2 / p-3 / p-4 / p-6 / p-8`).
Never use arbitrary pixel values.

```tsx
// ✅ CORRECT
<div className="p-4 gap-2">

// ❌ FORBIDDEN
<div style={{ padding: '17px', gap: '5px' }}>
```

### 3.4 Color tokens

**Rule:** Use semantic tokens (`bg-card`, `text-foreground`,
`border-border`). Never use raw hex.

```tsx
// ✅ CORRECT
<div className="bg-card text-foreground border border-border">

// ❌ FORBIDDEN
<div style={{ background: '#ffffff', color: '#1e1e1e' }}>
```

### 3.5 Typography

**Rule:** Use the Tailwind type scale (`text-xs / sm / base / lg / xl / 2xl`).
Never use `font-size:` inline.

### 3.6 Loading states

**Rule:** Use `Skeleton` or `Skeleton-helpers` from the shared UI
kit. Never roll a custom spinner outside `<button>` loading states.

```tsx
// ✅ CORRECT
import { Skeleton } from '@/modules/shared/components/ui/skeleton';
{isLoading ? <Skeleton lines={5} /> : <List items={…} />}

// ❌ DISCOURAGED — custom CSS spinner
{isLoading ? <div className="spinner-custom"/> : …}
```

### 3.7 Empty states

**Rule:** Use `EmptyState` from `@/modules/finance/components/EmptyState`
for any data-empty case.

```tsx
import { EmptyState } from '@/modules/finance/components/EmptyState';
{rows.length === 0 ? <EmptyState title="لا توجد فواتير" description="…" /> : <Table />}
```

### 3.8 Error handling

**Rule:** Wrap finance surfaces in `FinancialErrorBoundary`. Use
`sonner` toasts for transient errors elsewhere.

```tsx
// ✅ CORRECT — finance surface
<FinancialErrorBoundary>
  <DebtCard customerId={…} />
</FinancialErrorBoundary>

// ✅ CORRECT — transient
toast.error('فشل حفظ السجل');
```

### 3.9 Tables

**Rule:** Use `DataTable` (shared, generic) for short lists,
`WindowedList` for > 200 rows, or a domain-specific table from the
Financial UI Kit (e.g. `OutstandingTable`).

### 3.10 Forms

**Rule:** Use `react-hook-form` + Zod for validation. Use shared
`<Input>`, `<Select>`, `<Textarea>` primitives. Submit via the
domain hook (`modules/<x>/hooks/`) which calls `modules/<x>/api/`.

### 3.11 Modals / sheets

**Rule:** Use shared `<Dialog>` for desktop modals, `<Sheet>` for
side panels. Never use `window.alert` / `window.confirm`.

### 3.12 Keyboard shortcuts

**Rule:** Every workspace surface should support Alt+letter
shortcuts (per V20.7 charter). Use the shared
`KeyboardShortcutHelp` overlay (Cmd+/ to open).

### 3.13 RTL support

**Rule:** Every component must render correctly in RTL. Use
Tailwind's `rtl:` modifier and CSS logical properties
(`me-`, `ms-`, `pe-`, `ps-`).

## 7. Financial UI usage guide

### 7.1 When to display a money value

Always use a Financial UI Kit primitive. For one-off displays:

```tsx
import { formatKwdLabel } from '@/lib/kwd';
<span className="font-mono">{formatKwdLabel(row.amountKd)}</span>
```

### 7.2 When to display a sum

Ask the backend. If the sum is **derived from a fixed list of
backend-provided rows** (e.g. table totals), the backend must
provide the `totalKd` field directly.

If the sum is **dynamic based on user selection** (e.g. checkbox
selection in a transfer dialog), use `sumKwdStrings` from
`web/src/lib/kwd.ts` — this is the only allowed user-driven sum.

```tsx
import { sumKwdStrings } from '@/lib/kwd';
const totalSelected = sumKwdStrings(selectedRows.map(r => r.priceKd));
```

### 7.3 When to display a difference

For backend-computed diffs (e.g. `paidKd = amount - remaining`),
the backend must compute and provide `paidKd` directly. For
user-driven diffs, use `subtractKwdStrings` from `web/src/lib/kwd.ts`.

### 7.4 When to display a percentage

Backend computes; frontend renders as a string with the canonical
percent format:

```tsx
<span>{row.collectionsRatePercent}%</span>
```

### 7.5 When to display a status / level / stage

Use the matching badge primitive (`RiskBadge`, `FraudBadge`,
`AgingBadge`, `CollectionsStageBadge`, `PromiseStatusBadge`,
`PaymentStatusChip`).

### 7.6 When to display a financial KPI

Use `KPIWidget` or `FinancialStatCard`. Both consume pre-formatted
strings from the `observability/overview` API.

```tsx
<KPIWidget label="إجمالي الديون" value={kpi.totalDebtKd} variant="warning" />
```

### 7.7 When to display a customer financial summary

Compose from `Customer360FinancialBreakdown`,
`CustomerFinancialHeader`, `DebtCard`, and `FinancialTimeline`.
Never roll your own.

## 8. Forbidden patterns (full list)

| Pattern | Why | Where to put it instead |
| --- | --- | --- |
| `parseFloat(amountKd)` | Loses fils precision | Backend computes; frontend renders. |
| `Number(amountKd)` | Same | Same |
| `+amountKd` (unary) | Same | Same |
| `amountKd.toFixed(N)` outside `lib/kwd.ts` | Re-formats canonical string; risks rounding drift | `formatKwdAmount` / `formatKwdLabel` |
| `KWD_SUFFIX` constant outside `lib/kwd.ts` | Duplicates canonical formatter | Import from `lib/kwd.ts` |
| `function formatKwd*` outside `lib/kwd.ts` | Same | Same |
| `array.reduce((s, x) => s + parseFloat(x.amountKd), 0)` | Frontend aggregation | Backend computes the total. Use `sumKwdStrings` only when sum is user-selection-driven. |
| `Math.max(-balance, 0)` on a money value | Frontend financial derivation | Backend exposes the derived field. |
| `Math.round(amountKd * 100) / 100` | Rounding policy is the ledger's | Backend rounds. |
| Raw hex colour | Bypasses design tokens | Use Tailwind / CSS variables. |
| Inline `style={{ padding: '17px' }}` | Bypasses 4pt grid | Use Tailwind classes. |
| `window.alert` / `window.confirm` | Blocks the event loop; not RTL-safe | Use `<Dialog>` / `<Sheet>` from shared UI. |
| `dangerouslySetInnerHTML` | XSS surface | Use React text rendering. |
| Direct `apiJson` / `apiFetch` inside `modules/<x>/components` | Bypasses typed API layer | Use hooks in `modules/<x>/hooks/` calling typed clients in `modules/<x>/api/`. |
| Deep relative imports across modules (`../../<other>/`) | Breaks barrel contract | Use `@/modules/<other>` (barrel). |
