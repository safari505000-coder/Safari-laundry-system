## 1. نبذة عن النظام

**Safari ERP** منصّة تشغيل متكاملة لمجموعة مصابغ سفاري. تدير في مكان واحد:

- الفروع والموظفين والصلاحيات حسب الدور (RBAC)
- الطلبات والفواتير ونقاط البيع (POS)
- العملاء والاشتراكات والمحافظ والديون
- المدفوعات (نقدي / KNET / روابط دفع UPayments)
- السجل المحاسبي بنظام **القيد المزدوج** (Double-Entry Journal)
- الرواتب والمصروفات والتقارير المالية

**القنوات:**
| القناة | الوصف |
|---|---|
| واجهة الويب (ERP) | لوحة الموظفين/الإدارة — `www.safariomni.com` |
| تطبيق العميل | Expo / React Native |
| تطبيق الموظف | Expo / React Native |
| موقع الشركة التسويقي | `apps/public-web` (غير منشور حاليًا) |

## 5. المسار — خطة الإصلاحات القادمة

### 🔴 حرج (Critical)

| البند | لماذا | الإجراء المقترح |
|---|---|---|
| تفعيل `JOURNAL_FAIL_CLOSED_CRITICAL` بالإنتاج | الكود مدمج لكن العلم **مطفأ افتراضيًا** (سلوك قديم) | تفعيله بعد التأكد من اكتمال شجرة الحسابات + مراقبة `JournalFailureLog` |
| OTP لتسجيل دخول العميل | الدخول حاليًا قد يكون بالهاتف فقط بدون مزوّد SMS حقيقي | ربط مزوّد رسائل فعلي + فرض OTP |

### 🟠 عالي (High)

| البند | لماذا | الإجراء المقترح |
|---|---|---|
| نشر موقع الشركة | الزر "العودة للموقع" يلفّ على نفس الـ ERP | تعديل إعداد Render (إزالة تحويل apex→www) + ربط `safariomni.com` بخدمة الويب |
| تأمين ميزة الشحن التلقائي | لا منع تكرار، لا موافقة عميل، واجهة UPayments غير مؤكّدة | إضافة مفتاح منع تكرار + موافقة صريحة + التحقق من الـ API قبل التفعيل (الكود محفوظ بفرع held) |

### 🟡 متوسط (Medium)

| البند | لماذا | الإجراء المقترح |
|---|---|---|
| استقرار اتصال الموبايل | الـ IP يتغيّر مع الشبكة فيكسر الباركود | استخدام `expo start --tunnel` لرابط ثابت، أو IP ثابت للجهاز |
| قرار Migration B | تنظيف السجل القديم معلّق | مراجعة منفصلة ثم رفع أو حذف |
| إعداد بوابة النشر | `RENDER_DEPLOY_HOOK` غير مضبوط | ضبط السر في GitHub لأتمتة النشر |

### 🟢 منخفض (Low / دين تقني)

| البند | لماذا | الإجراء المقترح |
|---|---|---|
| تقسيم `orders.service.ts` | ملف ضخم (~3800 سطر) = صعوبة صيانة | تفكيكه لخدمات أصغر تدريجيًا |
| رفع بذرة البيانات الأساسية | جاهزة محليًا فقط | مراجعتها ودمجها في `main` |

## 6. الخلاصة

النظام **في حالة جيدة وآمنة بعد الدفعات الأخيرة**: الأمان والسلامة المالية والاختبارات قوية، والقاعدة الأساسية مستقرة. أبرز ما تبقّى هو **عمل تشغيلي/بنية تحتية** (نشر موقع الشركة، تفعيل علم القيد المالي، استقرار الموبايل) أكثر من كونه ثغرات في المنتج نفسه. لا يحتاج النظام إعادة كتابة — يحتاج إكمال خطوات النشر والتفعيل المتبقّية.
